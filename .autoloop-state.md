## Hard-won lessons (do not relearn these)

- Long sessions cost ~3.3x per call versus short ones. Finish one issue, stop.
- Delegating a big read-heavy write (like the 2300-line spec) to a subagent
  keeps this context small and works well — but VERIFY its output. The spec it
  produced claimed MIT; the project is AGPL-3.0. Check licence, counts and any
  claim it makes about the repo rather than trusting the summary.
- A failing test is a hypothesis, not a nuisance. Every "broken test" so far
  turned out to be a real product bug.
- Verify a fix by breaking it, and check HOW it failed: a build error proves
  nothing. Sabotage the data, not the types.
- When unmarshalling YAML into Go structs, a path item holds non-method keys
  (`parameters`) beside the methods — decode values as yaml.Node and filter.
- Absence and zero are different facts on every read path ("no samples" is not
  0% uptime). Aggregates must store their sample count to stay mergeable.
- Enum values live in the schema CHECK constraints (migrations/0001_init.sql).
  Read them before validating in Go — keyword_mode is absent_ok/must_contain/
  must_not_contain, not what you would guess.
- Test helpers already exist: seedMonitor (patch_test.go), testServerWithDB and
  seedUser (server_test.go), doJSON (channels_test.go), openTestDB (store).
  Check before adding one; a redeclaration costs a build-fail round trip.
