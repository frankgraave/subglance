**The shell (`web/src/shell/`, `web/src/wall/`)**: `App.tsx` owns the two
preferences and the two shortcuts; everything below is presentational.
preferences.ts is pure (layout + sidebar, localStorage-agnostic, storage that
throws fails open). `effectiveLayout()` is the viewport's veto: Rows and Compact
fall back to Cards below 640px, and the stored preference is NOT rewritten.
Status wall replaces the whole page (`LiveDashboard` returns `<StatusWall/>`
before the `Dashboard` branch) — hiding the chrome is why it exists, so it
carries the §6 stale signal on the canvas instead of in a banner. Its clock is a
second-resolution store separate from `useNow` (30s) on purpose.
The workbench survives behind the beaker button in the topbar, not in the nav.

**Live data (`web/src/live/`)**: api.ts fetches once, connection.ts owns the
EventSource as a plain class, events.ts parses, apply.ts folds (pure),
useLiveMonitors.ts glues it to TanStack Query. **The query cache is the only
home for the list.** A failed heartbeat is `pending`, never `down`.
`hello.gap`/`lagged` -> invalidate, do not patch. Backoff 1/2/5/10/30s.

**Serving the UI**: the frontend builds into `internal/webui/dist` (NOT
web/dist), embedded with `//go:embed all:dist`. Keep the committed
`dist/.gitkeep` and `emptyOutDir: false`. `make dist` = web-build + build.

**API**: `Server.requireMonitor` (internal/api/monitors.go) is the single place
answering "does this monitor exist" for sub-resource reads.

**Frontend in `web/`**: React 19, Tailwind v4, oxlint, vitest, TanStack Query.
`src/styles/tokens.css` is the ONLY file allowed a colour (tokens.test.ts).
Theme: `[data-theme]` on <html>, pre-paint script allowed by a CSP hash.
`src/monitors/` is all presentational; `Dashboard` takes a `layout` prop
(`rows` | `cards` | `compact`) and a `banner` slot. One breakpoint, 640px, in
src/layout/useMediaQuery.ts and monitors.css; breakpoint.test.ts asserts they
agree — shell.css and wall.css media queries must use 640 too.

## Hard-won lessons
- Long sessions cost ~3.3x per call. Finish one issue, stop.
- A failing test is a hypothesis. Verify a fix by breaking it and check HOW it
  failed: a build error proves nothing. Sabotage logic, not types.
- **Types are assumptions, not measurements.** Curl the real binary before
  trusting a wire type (`ApiMonitor.id` is a JSON number, not a string).
- End-to-end proof is cheap: build `./cmd/subglance`, run with `-data-dir
  /tmp/...`, POST /api/v1/setup (email+password), then curl the built assets.
- Write files via a python heredoc; `&` backgrounding is rejected.
- Tailwind v4 needs `@theme inline`; plain `@theme` freezes one theme.
- Absence and zero are different facts on every read path.
- Enum values live in internal/store/migrations/0001_init.sql CHECK constraints.
- jsdom: no layout (pass an explicit `width`), no `matchMedia`, no EventSource.
- oxlint rejects setState in an effect and refs read during render: use
  useSyncExternalStore. A .tsx exporting helpers trips only-export-components.
- Counts render as `<b>5</b> down`, so getByText(/5 down/) never matches.
