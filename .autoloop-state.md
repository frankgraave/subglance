## Hard-won lessons
- Long sessions cost ~3.3x per call. Finish one issue, stop.
- A failing test is a hypothesis. Verify a fix by breaking it and check HOW it
  failed: a build error proves nothing. Sabotage logic, not types.
- **Types are assumptions, not measurements.** `ApiMonitor.id` was typed
  `string` while Go sends an int64 as a JSON number; every live update would
  have missed its row. Curl the real binary before trusting a wire type.
- End-to-end proof is cheap: `go build`, run with `-data-dir /tmp/...`, POST
  /api/v1/setup (email+password only), `curl -sN` the stream. interval_s min 20.
- Write files via a python heredoc; `&` backgrounding is rejected, use
  background=true. git cannot un-ignore inside an ignored dir.
- Tailwind v4 needs `@theme inline`; plain `@theme` freezes one theme.
- Absence and zero are different facts on every read path.
- Enum values live in internal/store/migrations/0001_init.sql CHECK constraints.
- Helpers exist: seedMonitor, testServerWithDB, seedUser, doJSON, openTestDB,
  `contains` (validate_test.go — do not redeclare).
- jsdom: no layout (pass an explicit `width`), no `matchMedia` (stub it).
- oxlint rejects setState in an effect, refs read during render and
  `Date.now()` during render: use useSyncExternalStore, or set state during
  render guarded by a "did this prop change" check (see useLiveMonitors). A
  .tsx exporting helpers trips only-export-components: use a sibling .ts.
- Counts render as `<b>5</b> down`, so getByText(/5 down/) never matches.
