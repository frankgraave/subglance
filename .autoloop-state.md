**Backend**: `GET /api/v1/monitors?heartbeats=N` embeds each monitor's beats
(oldest first) so one request draws the whole grid. Backed by
`store.RecentHeartbeatsForAll` — one window-function query, not N+1.

**Frontend lives in `web/`**: React 19, Vite 8, Tailwind v4, oxlint, vitest.
Targets from the root Makefile: web-install, web-test, web-lint, web-build.
CI has a fifth job, `web`, running test + lint + build.

`web/src/styles/tokens.css` is the ONLY file allowed to contain a colour.
`web/src/styles/tokens.test.ts` enforces both sides. Use a token: `bg-surface`,
`text-ink-2`, `var(--glow-up)`.

Theme: `[data-theme]` on <html>, preference in localStorage, applied by a
pre-paint script in `web/index.html` that duplicates `web/src/theme/theme.ts`.

`web/src/heartbeat/` holds the brand component: `model.ts` (pure geometry,
node-tested), `HeartbeatBar.tsx`. `web/src/monitors/` holds the dashboard:
`model.ts` (partition/filter/summarise/describeTransitions, pure),
`types.ts` (+`fromApi`), `Led.tsx`, `MonitorRow.tsx`, `MonitorTable.tsx`,
`Dashboard.tsx`, `demo.ts`, `Workbench.tsx`. All presentational and
props-driven — SUB-26 feeds them, it does not rewrite them.

Component CSS is imported from `src/index.css`, never from the .tsx.
`App.tsx` is a tabbed workbench (dashboard + heartbeat + tokens), not routing.

## Hard-won lessons (do not relearn these)

- Long sessions cost ~3.3x per call versus short ones. Finish one issue, stop.
- A failing test is a hypothesis. Verify a fix by breaking it and check HOW it
  failed: a build error proves nothing. Sabotage the logic, not the types.
- The terminal tool blocks a command whose TEXT resembles a long-lived watcher,
  even a heredoc merely writing a file that mentions one. Reword the file.
- Tailwind v4 needs `@theme inline`; plain `@theme` freezes one theme.
- Absence and zero are different facts on every read path.
- Enum values live in internal/store/migrations/0001_init.sql CHECK constraints.
- Go helpers: seedMonitor, testServerWithDB, seedUser, doJSON, openTestDB.
- jsdom has no layout: getBoundingClientRect is all zeroes. HeartbeatBar needs
  an explicit `width` prop in tests or it renders empty.
- `getByRole("table")` is ambiguous: every HeartbeatBar renders its own sr-only
  table. Match the monitor table by its caption's accessible name.
- oxlint react(set-state-in-effect) fires on any setState in an effect, and
  only-export-components fires on a non-component export from a .tsx.
