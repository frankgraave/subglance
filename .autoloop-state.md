# SubGlance — autonomous work loop handoff

This file is the memory between runs. Each run reads it first and rewrites it
last. It exists because a cron run starts with an empty context: without this,
every run would spend its first (and most expensive) calls rediscovering where
the project stands.

Keep it SHORT. It is read on every run, so length here is a recurring cost.
Aim for under 60 lines. Delete anything that is no longer true rather than
appending to it — this is a current-state file, not a log. The log lives in
Linear comments and git history, which are the durable record.

## Standing constraints

- Go directive stays at 1.25.0. CI pins Go 1.25.14 and both linter versions;
  bumping the directive means checking a golangci-lint release exists that was
  built with that Go.
- Short test suite must stay hermetic: `go test -short` may not touch the
  network. Network tests sit behind SUBGLANCE_TEST_NETWORK=1.
- Never `git push --force`, never rewrite history.
- Commit messages in Dutch. Code, comments and docs in English.
- Fix lint findings; do not suppress them.
- golangci-lint under `systemd-run --scope -p MemoryMax=1500M`: the host has
  3.7GB and an unbounded lint run has taken the gateway down before.

## Hard-won lessons (do not relearn these)

- Long sessions cost ~3.3x per call versus short ones. Finish one issue, stop.
- A failing test is a hypothesis, not a nuisance. Three "broken tests" so far
  were all real product bugs.
- Verify a fix by breaking it, and check HOW it failed: one sabotage produced a
  build error instead of a test failure, which proves nothing. Rewrite the
  sabotage so the code still compiles.
- Absence and zero are different facts on every read path. "No samples" must
  not serialise as 0% uptime; the API uses a nullable field for that.
- Aggregates need their sample count stored, or they cannot be merged later.
- On PATCH, "absent" and "zero" differ too: request fields are pointers, and
  validation runs on the merged monitor, not on the request.
- Enum values live in the schema CHECK constraints (migrations/0001_init.sql).
  Read them before validating in Go — keyword_mode is absent_ok/must_contain/
  must_not_contain, not what you would guess.
