SubGlance — design review

Two clickable mockups. Nothing here is wired to a backend: the data is fixed and the interactions are simulated, so it is safe to click anything.

Dashboard layouts dashboard-directions.html
Four ways to show the same fourteen monitors. The layout is a real setting — pick one from the grid icon in the toolbar and it is remembered.
Rows · Cards · Compact · Status wall
Try: “Simulate outage”, the live check ticks, ⌘B to collapse the sidebar
Components & forms components.html
Everything the dashboard does not cover — the other 80% of the product. Add-monitor form, inline renaming, switches, buttons, dialogs, and the empty/loading/error states.
Try: click a monitor name to rename it, “Test now”, ⌘K for the command palette, “Delete monitor…”

Both pages remember your theme and layout in localStorage. If something looks stale after a git pull, hard-refresh with ⌘⇧R.

The reasoning behind every choice here is written down in docs/DESIGN.md — tokens, the LED, layouts, accessibility, and the things we deliberately do not do.
