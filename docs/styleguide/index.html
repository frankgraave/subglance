SubGlance — living style guide

Every value on this page is read out of web/src/styles/tokens.css when the page is generated, and this page loads that same file as its stylesheet. There is no second copy to drift. A token that changes changes here; a token that is deleted disappears from the table.

This page is not the guarantee. Documentation that is only read when someone remembers to read it is how a design system drifts in the first place — this repository already had 1797 lines of design documentation while 88 loose pixel values accumulated across 26 stylesheets. The guarantee is web/src/styles/tokens.test.ts, which fails the build on a literal colour, size, type role, leading, tracking, spacing, radius, border, depth value or breakpoint. This page exists so a human can see what the guards enforce, and so a reviewer can tell whether a new rung deserves to exist. When the two disagree, the test wins and the page is the thing that is broken.

Controls

The height a row of interactive chrome settles on, and the square a compact icon control occupies.

TokenValueWhat it is for
--control-h 36px There is deliberately no `--track-caps`, `--track-badge` or `--track-mono`. All three existed on reasoning that sounds right and measures wrong: uppercase needs opening up, a mono badge is already wide, a monospace face
moresits on a fixed advance so the body correction does not apply. Measured against the reference style, none of it holds: it sets one absolute -0.32px on the body and overrides it nowhere — sans and mono, sentence case and uppercase, badges and headers all inherit the same value. The tightening is a house style applied to the page, not a per-face or per-casing fix. Every exception we had pushed letters apart while the style we were aiming at pulled them together. The caps one was the worst: +.09em at 12px is +1.08px per pair against the body's -0.32px, so section labels sat 1.4px per pair wider and read as spaced-out small caps rather than as a quiet header. Mono opting out is what made panel headers and IDs read wide. If a future face genuinely needs its own value, add it with a measurement attached, not with an argument. Space moves in steps of 4px. Named so a row's rhythm is a decision that can be changed in one place, not 40 ad-hoc paddings. Control height. Not a spacing step: it is the height a row of interactive chrome settles on, and stating it beats padding chosen to reach it.

Radius

Radii are concentric: an inner corner is the outer radius minus the inset between them, so a nested box never looks pinched. The guard checks the arithmetic, which is why the inset has to be a token too.

TokenValueWhat it is for
--r-2xs 2px Shape. Four steps in use, and the gaps between them are deliberate: 2px for a mark, 6px for anything you click, 8px for a panel, 12px for the card that frames panels.
more`--r-2xs` exists because the lamp drew itself at 2.5px only while the ladder stopped at 4px, and a fractional radius is the same defect the type scale already rejected: what the engine does with the half pixel depends on the device pixel ratio, so the lamp was not the same shape on every screen. `--r-xs` (4px) is kept for compatibility but is not part of the ladder in use: a control at 4px reads as a mark rather than as something pressable, and the jump from 2 to 6 is what keeps those two jobs apart.
--r-xs 4px
--r-sm 6px
--r-md 8px
--r-lg 12px
--r-pill 999px Fully round, for a pill. Not a rung on the ladder and deliberately outside it: the ladder states how tight a *corner* is, and this states a shape — whatever the box's height, the ends are semicircles.
moreHence a number far past any real height rather than `50%`, which on a box wider than it is tall draws an ellipse.

Depth

Four named rungs, spaced by ten so a scrim can take rung-minus-one. Every bare z-index in the product was replaced by one of these after a tooltip at z-index 10 was clipped by a topbar at 20.

TokenValueWhat it is for
--z-chrome 20 The stacking ladder. Every z-index in the product is a rung on this list and nothing writes a bare number.
moreThat is the whole point: the defect these tokens replace was a tooltip at 10 clipped under a sticky bar at 20, and the obvious repair — raise the tooltip — is the same move that produced 20, 40, 41, 50, 51 and 100 in the first place. Each of those was correct against whatever it was written next to and wrong against something in another file, because nowhere stated the order. Here the order is the artefact, in one place, in reading order, so "is a tooltip above the topbar" is answered by looking at two lines rather than by grepping six stylesheets. The rungs are spaced by ten, which is not decoration: a layer that needs a companion sitting just under it (a scrim under its panel) takes `rung − 1` without a new token and without colliding with the rung below. Read top to bottom, this is the product's answer to "what covers what": page chrome is above the page, a floating readout is above the chrome because it is a reply to something you pointed at in the chrome's shadow, a modal overlay is above everything because it owns the screen while it is open, and the skip link is above even that because it is the one control that has to be reachable when everything else has gone wrong. Sticky page chrome: the topbar, the wall's exit control.

--z-overlay 60 Modal overlays: the drawer and the phone navigation, with their scrims one below at `calc(var(--z-overlay) - 1)`.
--z-skip 100 The skip link, which must outrank everything it skips past.

Accent and overlay

The accent fills controls; it never marks data. Its ring, its ink and the scrim that dims the page behind an overlay belong to the same family and are stated together so a new control cannot invent its own.

TokenValueWhat it is for
--accent oklch(.546 .245 262.881) The control accent (§2.8). It sits in :root rather than in the two theme blocks because it is deliberately the same colour in both: an accent that shifts with the theme is a second thing to remember and a second thing
moreto get wrong. It fills controls and nothing else -- a segment you can pick, a primary button, a focus ring. Faces and weights

A face is applied as a role, never as a family name -- the guard rejects a raw font stack in a stylesheet. Weights, tracking and the OpenType features that make figures line up in a table live here too, because a column of numbers that is not tabular reads as jitter.

TokenValueWhat it is for
--font-sans "InterVariable", ui-sans-serif, system-ui, -apple-system, sans-serif
--font-mono "CommitMono", ui-monospace, "SF Mono", Menlo, monospace
--feat-sans "calt" 1, "ccmp" 1, "locl" 1, "kern" 1, "cv01" 1 Layout features, pinned per role rather than left to the browser's defaults, which differ per engine and per face. Verified against the shipped files, not copied from a specimen page.
moreThe sans keeps only what is structurally necessary — contextual alternates, glyph composition, localised forms, kerning — plus `cv01`, the face's alternate figure one, which carries a foot serif so a bare `1` cannot be read as a lowercase `l` in a monitor name. Everything discretionary is therefore off, including `tnum` and `zero`: the sans sets words and proportional figures read better in them, because anything measurable is set in the mono instead (§2.5). The mono takes the opposite position. `ss01`-`ss05` are the face's contextual sets for code-like text — arrow, comparison and equality sequences are drawn as one mark rather than two colliding ones, which is what makes a status line or a header value scan. `cv01` is its single-storey `a`, `cv05` a narrower `@`, `cv06` straightened `6`/`9`, and `cv11` the alternate `1`, all chosen so characters that differ by a stroke are told apart at 13px. Figures need no `tnum`: the face is monospaced, so every figure is already one column wide.
--feat-mono "ss01" 1, "ss02" 1, "ss03" 1, "ss04" 1, "ss05" 1, "cv01" 1, "cv05" 1, "cv06" 1, "cv11" 1
--ligatures-sans common-ligatures contextual
--numeric-sans normal
--render-sans optimizeLegibility
--ligatures-mono none Mono switches on what makes it legible and off what fuses characters. `slashed-zero` is the one that matters: IDs, latencies and timestamps are set in mono precisely so 0 cannot be read as O.
moreLigatures are off outright — a mono ligature turns `->` or `!=` inside a URL or an error string into a glyph that is no longer the characters it stands for. `tabular-nums` belongs to the face and not to seven call sites: if the rule is "anything measurable is mono", every mono digit is already meant to line up.

--render-mono geometricPrecision

Breakpoints

Documented here, enforced as literals. A custom property inside a media query never resolves — verified in Chromium, not assumed — and it fails silently, so the block is simply dropped and the layout is quietly wrong at one width.
